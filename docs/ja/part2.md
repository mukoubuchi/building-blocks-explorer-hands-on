# 演習

所要時間: 25 分（経過時間: 30–55 分）

Explorer で以下の架空のシナリオに取り組みます。出典を記録し、事実と仮定を分けます。実際の認証情報の入力や製品のデプロイは行いません。課題 2 のローカル文書作成は実施します。

## 課題 1: 文書アシスタント {#exercise-1}

10 分

### ステップ 1: 候補を探す

新しい会話を始め、貼り付けます。

```text
架空の小売企業が、承認済みの商品資料や規程から、店舗担当者の質問に答えるアシスタントを検討している。
出典を示し、根拠がなければ回答が見つからないと伝える必要がある。

カタログツールで Building Blocks の候補を 2 つ探し、比較する。
比較項目は、選定理由、出典 URL、提供物、前提条件、検証すべき点。

確認質問は最大 2 つまでとし、1 回に 1 つずつ聞く。
インストールやデプロイは行わないこと。
```

質問された場合は、入力は架空の PDF/テキスト文書、利用者は店舗担当者とします。

### ステップ 2: 出典を確認する

各 README を開き、提供物と前提条件を確認します。リンクが開かなければ [Building Blocks の概要](https://github.com/ibm-self-serve-assets/building-blocks) から探し、確かめられない点は未確認とします。

候補例: [RAG](https://github.com/ibm-self-serve-assets/building-blocks/tree/main/data/pipelines/rag)、[Agent Builder](https://github.com/ibm-self-serve-assets/building-blocks/tree/main/ai/agents/agent-builder)。根拠があれば別の候補でも構いません。

### ステップ 3: 結果を記録する

| 項目 | 内容 |
| --- | --- |
| 業務課題 | 1 文で説明 |
| 候補 2 つ | 名前と選定理由 |
| 根拠 | 出典 URL、確認日、提供物、前提条件 |
| 次の検証 | 確かめることを 1 つ |

## 課題 2: 秘密情報管理の引き継ぎ {#exercise-2}

15 分

### ステップ 1: 適するブロックを探す

新しい会話を始め、貼り付けます。

```text
架空のチームがデモ用スクリプトへ認証情報をコピーしており、秘密情報と機械のアクセスを一貫した方法で管理したいと考えている。

カタログツールで適する Building Block を探し、選定理由、出典 URL、前提条件を示す。
文書検索だけでは足りない理由も説明に含める。

確認質問は最大 2 つまでとし、1 回に 1 つずつ聞く。
認証情報の要求、インストール、キーの更新、デプロイは行わないこと。
```

質問された場合は、利用者はデモ開発チーム、接続先はテスト用 API とします。出典を確認します。参照先の例は [Secrets Management](https://github.com/ibm-self-serve-assets/building-blocks/tree/main/automation/secure/non-human-identity-and-secret-management/secrets-management) です。

### ステップ 2: 引き継ぎ文書を作る

```text
エンジニア向けの use_case_summary.md をワークスペース直下に作成する。

業務課題、利用者、範囲、候補と理由、出典 URL、前提条件、未解決の質問 2 つ、次の検証と成功条件を含める。

確認した事実と仮定は分けて記載し、扱う範囲はこの架空のシナリオに限る。
インストール、サービスの設定、デプロイは行わないこと。
```

確認された場合は、依頼したローカル文書の作成を承認します。Bob が書き込めない場合は、回答をワークシートへコピーします。

### ステップ 3: 結果を点検する

出典が選定理由を裏付けていること、未解決の質問が 2 つあること、成功条件を観察できることを確認します。例えば、ダミーの秘密情報を直接書かずに取得する検証を計画します。この時間内には実行しません。
