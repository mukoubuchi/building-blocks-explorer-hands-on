# まとめと次の会話

所要時間：5 分・経過時間：55〜60 分

約 3 分で記録を見直し、1 分でペアと 30 秒ずつ提案を話し、最後の 1 分でフィードバックを記入します。

## 結果を説明する

次の形を使います。

> 利用者は ____ に困っています。____ という理由で、____ を候補に挙げました。出典では ____ を確認できました。まだ ____ の検証が必要です。エンジニアとの次の一歩は ____ です。

必須課題のどちらかで完成させます。測定した事実、出典の記載、仮定を分けてください。根拠のない ROI や実装期間の数値を加えないようにします。

## 完了したこと

- [ ] Building Blocks と Explorer の役割を説明できる。
- [ ] uv／uvx を確認した。または、導入の問題を記録してペアで取り組んだ。
- [ ] カタログの根拠を使った。または、資料を読んだ代替演習と明記した。
- [ ] 文書アシスタントの候補を 2 つ提案した。
- [ ] 未解決の質問 2 つを含む、秘密情報管理の引き継ぎを作った。
- [ ] 本番利用できると断定せず、次の検証を説明できる。

追加のスキル導入は、完了の必須条件ではありません。実施した場合は、結果を別に記録します。

## 成果物を残す

`workshop-notes.md` またはワークシートと、作成した `use_case_summary.md` を保存します。別の Explorer の会話で同名の `use_case_summary.md` を使うと上書きされる可能性があるため、実験を続ける場合は課題ごとに異なるファイル名で保存してください。

提出すると決めた、架空のシナリオの内容だけを共有します。このサイトがワークシートやフィードバックを自動送信することはありません。終了後は演習用ワークスペースを閉じて構いません。必須課題ではクラウドのサービスを作成していません。

## 終了後に続けること

[Building Blocks の概要](https://github.com/ibm-self-serve-assets/building-blocks)から候補の前提条件を読み、エンジニアと検証計画を決めます。試行の前に、顧客が求める成果、データへのアクセス条件、成功指標、必要な環境を確認してください。
