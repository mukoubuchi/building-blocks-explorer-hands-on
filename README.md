[![License](https://img.shields.io/badge/license-Apache--2.0-blue)](LICENSE)

A **60-minute hands-on workshop**, available in English and Japanese. Use IBM Bob and the Building Blocks Explorer to ask independent catalog questions and receive sourced answers, then install a skill and a mode and draw an architecture diagram with Explorer's local installer.

IBM Bob must already be installed and usable. Participants install **uv during the session**; no separate Python, Git, Node.js, Docker, cloud account, or product deployment is required. The local installer does not start at present because of an upstream bug ([#262](https://github.com/ibm-self-serve-assets/building-blocks/issues/262)); until it is fixed, only exercises 1–3, which use the hosted catalog alone, can run.

## Repository structure

This repository follows [vector-search-hands-on](https://github.com/mukoubuchi/vector-search-hands-on): Material for MkDocs, English at `docs/`, Japanese at `docs/ja/`, modular CSS/JavaScript, instructor notes, and translation checks.

```text
.github/workflows/       # CI, translation checks, and Pages
lib/                     # Validation helpers and the MkDocs sitemap hook
setup/instructor/        # Facilitation, sources, and build requirements
docs/                    # English teaching pages and shared UI assets
docs/ja/                 # Japanese teaching pages
mkdocs.yml               # Bilingual navigation and site configuration
```

The inherited layout includes language switching, search, linked OS tabs, numbered step rails, code-copy buttons, and persistent checklists. Existing Milvus runtime services are not part of this Explorer workshop.

## Build and preview

Run these commands from the repository root after installing [uv](https://docs.astral.sh/uv/getting-started/installation/).

### macOS

```bash
uv venv
uv pip install --python .venv/bin/python -r setup/instructor/requirements.txt
.venv/bin/mkdocs build --strict
.venv/bin/python lib/validate_docs.py
.venv/bin/mkdocs serve --dev-addr 127.0.0.1:8000
```

### Windows PowerShell

```powershell
uv venv
uv pip install --python .venv/Scripts/python.exe -r setup/instructor/requirements.txt
.venv/Scripts/mkdocs.exe build --strict
.venv/Scripts/python.exe lib/validate_docs.py
.venv/Scripts/mkdocs.exe serve --dev-addr 127.0.0.1:8000
```

Open `http://127.0.0.1:8000/` or `http://127.0.0.1:8000/ja/`. The preview binds only to the local machine.

Page navigation uses Material's `navigation.instant`. The custom `overrides/partials/tabs.html` keeps the header navigation and its moving underline mounted while the page content changes. Page-specific scripts subscribe to Material's `document$` lifecycle.

The i18n plugin's automatic Material reconfiguration is disabled because its contextual alternate links conflict with instant navigation. Language roots and theme languages are configured explicitly; `language-switcher.js` retains the current page and reloads the localized theme when switching languages. The language links in the page head are relative, so they resolve under any project path, and `lib/ja_sitemap_hook.py` copies the sitemap into `ja/`, where Material looks for the Japanese one. When serving a built site on another port or under a project path, build with `SITE_URL` set to that preview URL so the sitemap matches.

The repository is public. The workflow `deploy-docs.yml` publishes the site to GitHub Pages at <https://mukoubuchi.github.io/building-blocks-explorer-hands-on/> (Japanese: <https://mukoubuchi.github.io/building-blocks-explorer-hands-on/ja/>) when the documentation on `main` changes; the repository variable `PAGES_ENABLED` is `true`, and the workflow can also be dispatched. Use the local preview above to check changes before pushing them.

## Maintenance conventions

- Keep this README, maintainer documentation, code comments, filenames, commit messages, and release notes in English. Japanese teaching content is intentional.
- Update corresponding English and Japanese teaching files in the same change. CI checks changed pairs; it does not certify translation meaning.
- Use Conventional Commits and explicit paths for staging. Review staged filenames and content before committing.
- Keep local tool configuration, credentials, conversation logs, and generated files out of Git.
- Building Blocks workshop ZIPs carry no README; `lib/validate_docs.py` fails when one appears under `setup/participant/`.
- Review the current upstream sources and run the instructor preflight before each workshop. The recap is checked against upstream commit `f721f5ec1915225ade62d8d0e780fe6b19aa58b8` dated September 9, 2026; catalog results remain dynamic.
- Use system fonts, existing Material CSS variables, and the inherited modular UI. Keep participant flows free of maintainer setup details.
- Before a release, run CI, review both languages and OS tabs in a headless browser, and rehearse the actual Bob flow on macOS and Windows. Documentation build success is not a Bob runtime test.
- Consider an annotated semantic-version tag for every pushed change. Reader-visible teaching changes warrant a release; release notes summarize behavior and materials, not a list of commits.

Push an annotated version tag and create its GitHub release with English notes. Initial version `v0.1.0` is a teaching draft pending a facilitated rehearsal.
